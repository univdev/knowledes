# 큰 작업을 전문 에이전트에 기본 위임하기

## 상태

채택됨

## 날짜

2026-05-29

## 배경

전역 오케스트레이터는 사용자의 요청을 이해하고 적절한 실행 경로를 고르는 역할이에요.
하지만 멀티 파일 변경, 여러 도메인이 섞인 기능, 플랫폼 제약이 걸린 작업까지 오케스트레이터가 직접 처리하면 탐색, 구현, 검증 책임이 한곳에 몰려요.

Charlang처럼 Apps in Toss, 타이머 상태, 오디오, 광고, 결제, 모바일 UI가 함께 얽힌 프로젝트에서는 작은 변경처럼 보여도 실제로는 여러 하위 시스템에 영향을 줄 수 있어요.
사용자가 매번 "서브에이전트에게 맡겨"라고 말하지 않아도 큰 작업은 기본적으로 분담되어야 해요.

## 결정

범위가 넓거나 여러 파일, 여러 도메인, 플랫폼 민감 영역을 건드리는 작업은 오케스트레이터가 기본적으로 전문 에이전트나 팀에 위임해요.
전역 하네스는 큰 작업의 위임 원칙을 갖고, 프로젝트 하네스는 자기 도메인에 맞는 구체적인 위임 기준을 둬요.

Charlang 프로젝트 하네스는 멀티 파일 변경, Apps in Toss 플랫폼 제약, UI와 타이머 상태가 함께 바뀌는 작업을 큰 작업으로 보고 기본 위임 대상으로 삼아요.

## 고려한 대안

- 사용자가 명시적으로 요청한 경우에만 위임하기
- 모든 작업을 팀 모드로 처리하기
- 오케스트레이터가 직접 구현하고 마지막에만 검증 에이전트를 호출하기

## 선택 이유

명시 요청에만 의존하면 사용자가 내부 복잡도를 알지 못하는 경우 위임이 늦어져요.
반대로 모든 작업을 팀 모드로 처리하면 단순 변경에도 비용이 커져요.

그래서 작업의 크기와 위험을 기준으로 위임 여부를 판단해요.
이 방식은 작은 수정의 속도는 유지하면서, 복잡한 변경에서는 탐색과 검증을 빠뜨리지 않게 해요.

## 트레이드오프

큰 작업 판단이 보수적이면 일부 작업에서 진행 단계가 늘어나요.
하지만 플랫폼 제약이나 사용자-facing UI가 얽힌 변경에서 검증 누락을 줄이는 이점이 더 커요.

프로젝트별 하네스가 같은 원칙을 공유하더라도 구체적인 기준은 프로젝트마다 달라질 수 있어요.

## 결과와 후속 작업

전역 하네스와 Charlang 프로젝트 하네스에 큰 작업 기본 위임 규칙을 추가했어요.
Charlang PR `feature/refine-pro-confetti-and-spacing`에는 프로젝트 내부 하네스 규칙 변경이 포함될 수 있지만, 전역 하네스 파일 변경은 Charlang 프로젝트 PR 밖의 별도 전역 설정 변경으로 봐야 해요.
