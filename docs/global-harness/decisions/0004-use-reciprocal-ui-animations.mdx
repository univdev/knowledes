# UI 닫힘 애니메이션을 열림의 역방향으로 맞추기

## 상태

채택됨

## 날짜

2026-05-29

## 배경

모바일 WebView에서는 다이얼로그, 하단 시트, 오버레이가 열리고 닫히는 짧은 순간도 사용자의 조작 확신에 영향을 줘요.
열릴 때는 애니메이션이 있는데 닫힐 때 즉시 사라지면, 사용자는 화면이 튄 것인지 정상적으로 닫힌 것인지 구분하기 어려워요.

Charlang의 PRO 구매 다이얼로그도 열림과 닫힘의 체감이 맞지 않는 부분을 보완할 필요가 있었어요.

## 결정

프로젝트 하네스의 기본 UI 규칙으로, 애니메이션이 있는 UI는 닫힐 때 열림 애니메이션의 역방향을 사용해요.
fade-in으로 열린 UI는 fade-out으로 닫고, slide-up으로 열린 UI는 대응되는 slide-down으로 닫는 식이에요.

이 원칙은 기능 요구사항이 아니라 인터랙션 품질 기준이에요.
사용자가 명시적으로 다른 전환을 요구하거나 접근성, 성능, 플랫폼 제약이 더 강하면 그 제약을 우선해요.

## 고려한 대안

- 닫힘 애니메이션을 컴포넌트마다 개별 판단하기
- 모든 닫힘을 즉시 처리하기
- 모션을 전역에서 완전히 금지하기

## 선택 이유

개별 판단에만 맡기면 같은 앱 안에서도 닫힘 체감이 흔들려요.
즉시 닫힘은 빠르지만, 모바일 다이얼로그와 오버레이에서는 조작 피드백이 부족할 수 있어요.

열림의 역방향을 기본값으로 두면 구현자는 매번 새 모션 언어를 만들 필요가 없고, 사용자는 화면 전환의 원인을 더 쉽게 이해해요.

## 트레이드오프

닫힘 완료를 기다려야 하므로 상태 제거가 몇백 밀리초 늦어질 수 있어요.
이때 중복 탭과 pointer event 처리를 함께 설계해야 해요.

모션을 줄여야 하는 접근성 설정이 생기면 애니메이션 시간을 줄이거나 끄는 별도 기준이 필요해요.

## 결과와 후속 작업

Charlang 프로젝트 하네스에 reciprocal UI animation 규칙을 추가했고, PRO 구매 다이얼로그는 닫힐 때 fade-out을 적용했어요.
전역 하네스 파일 변경은 Charlang feature PR의 코드 변경과 별개인 글로벌 설정 변경으로 기록해요.
