# 아키텍처

찰랑은 서버 없이 동작하는 Apps in Toss WebView 미니앱이에요.
React 화면, 타이머 상태 훅, Audio API 훅, 로컬 저장소, Apps in Toss SDK 브리지로 구성돼요.

## 전체 구성

```text
Toss App WebView
  -> React App
    -> First Run Tutorial
    -> Timer Page
      -> Wave Canvas
      -> Banner Ad
      -> Session Duration Dialog
    -> Chart Page
      -> Chart.js
      -> Banner Ad
    -> useCharlangTimer
      -> local storage
      -> domain rules
    -> useAudioEngine
      -> Web Audio API
    -> Apps in Toss SDK
      -> Ads
      -> Haptics
      -> SafeAreaInsets
```

## 기술 스택

- React 18, Vite, TypeScript
- `@apps-in-toss/web-framework`
- TDS Mobile 계열 패키지
- Chart.js
- lucide-react
- Web Audio API
- Canvas 2D API
- local storage 기반 저장

## 모듈 경계

`useCharlangTimer`는 타이머의 단일 상태 소스예요.
구간, 라운드, 사이클, 자동진행, 수동진행, 스킵, 완료 기록, 로컬 저장 복원을 담당해요.

`useAudioEngine`은 타이머 상태를 직접 바꾸지 않아요.
볼륨 값에 맞춰 틱톡 루프와 종료 알림음을 재생하고, 사용자 제스처 뒤 AudioContext를 열어요.

`TimerPage`는 조작과 표시를 담당해요.
시작, 멈추기, 이어하기, 다음 구간, 자동/직접 넘김, 볼륨, 차트 이동, 시간 조정 다이얼로그를 표시해요.

`FirstRunTutorialPage`는 첫 접속 사용자에게만 타이머 진입 전 3페이지 설명을 보여줘요.
완료 여부는 Apps in Toss Storage 래퍼를 통해 `charlang:tutorial-seen:v1`에 저장하고, 브라우저 개발 환경에서는 localStorage fallback을 사용해요.
hash route를 추가하지 않고 App 레벨에서 timer route 렌더링 전에만 가로채기 때문에 Toss 기본 네비게이션 흐름을 바꾸지 않아요.

`WaveCanvas`는 진행률과 세션 색상만 받아서 그려요.
집중과 긴 휴식은 물이 차오르고, 짧은 휴식은 물이 빠지는 방향으로 보여줘요.
튜토리얼에서도 같은 컴포넌트를 재사용하고, 화면별 진행률과 전환 시간만 별도 props로 조정해요.

`ChartPage`는 저장된 통계만 읽어서 최근 30일 막대 차트와 누적 시간 도넛 차트를 그려요.
타이머가 실행 중이어도 차트 페이지로 이동할 수 있고, 타이머 상태는 유지돼요.

`BannerAd`는 Apps in Toss 광고 SDK를 감싸요.
브라우저 개발 환경에서는 지원 여부 확인과 예외 처리를 통해 화면이 깨지지 않게 해요.

## 데이터 흐름

사용자가 시작 버튼을 누르면 AudioContext를 unlock하고 타이머가 `running` 상태로 바뀌어요.
타이머는 250ms 간격으로 실제 시간 차이를 계산하고, 화면에 표시되는 남은 시간은 초 단위로 갱신해요.
브라우저가 잠깐 멈췄다가 돌아와도 `Date.now()` 기준으로 보정하기 때문에 setInterval 누락에 덜 민감해요.

구간이 완료되면 실제 진행 시간이 통계에 더해져요.
집중을 끝까지 완료한 경우에만 완료한 집중 수가 증가해요.
긴 휴식까지 끝났고 해당 사이클에 스킵이 없었다면 완료한 사이클 수가 증가해요.

환경설정과 상태는 로컬 저장소에 나뉘어 저장돼요.

- preferences: 볼륨, 진행 모드, 세션별 시간
- stats: 일자별 완료 수와 누적 시간
- timer snapshot: 현재 구간, 라운드, 남은 시간, 경과 시간, 상태

## 외부 의존성

Apps in Toss SDK는 광고, 햅틱, Safe Area 계산에 사용돼요.
SDK가 없는 일반 브라우저에서는 try/catch와 fallback을 사용해야 해요.
초기 개발 중 브라우저에서 흰 화면이 뜬 원인은 앱 환경 전용 API를 방어하지 않고 호출한 것이었고, 이후 지원 여부 확인을 추가했어요.

배포 자동화는 GitHub Actions에서 `APPS_IN_TOSS_API_KEY` secret을 읽어 `npx ait deploy`를 실행해요.
문서와 코드에는 실제 키 값을 남기지 않아요.

## 바꾸면 위험한 부분

- `useCharlangTimer`의 완료/스킵 규칙은 통계와 화면 흐름을 동시에 바꿔요.
- 긴 휴식 스킵은 다음 집중으로 돌아가야 하며, `00:00`에 멈춘 채 스킵 버튼이 사라지면 안 돼요.
- 짧은 휴식 물결은 진행률이 반대로 계산돼야 해요.
- custom toast와 하단 조작 영역은 Apps in Toss `SafeAreaInsets`와 CSS env fallback을 함께 고려해야 해요.
- 세션 시간 조정은 input focus 확대를 피하기 위해 버튼 기반으로 유지해야 해요.
