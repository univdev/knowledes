# Apps in Toss WebView로 구현하기

## 상태

채택됨

## 날짜

2026-05-24

## 배경

찰랑은 Toss 앱 안에서 실행되는 미니앱으로 출시하는 것이 목표였어요.
따라서 일반 웹앱처럼 브라우저만 기준으로 만들면 광고, 햅틱, safe area, Toss 기본 네비게이션, 배포 방식에서 문제가 생길 수 있었어요.

## 결정

React, Vite, TypeScript 기반의 Apps in Toss WebView 앱으로 구현해요.
공식 Apps in Toss SDK와 Granite 설정을 사용하고, Apps in Toss API는 일반 브라우저에서도 실패하지 않도록 방어 코드를 둬요.

## 고려한 대안

- 일반 React 웹앱으로 먼저 만든 뒤 나중에 Apps in Toss에 맞추기
- React Native 기반으로 만들기
- 서버 기반 앱으로 만들고 WebView에는 얇은 화면만 두기

## 선택 이유

타이머, 차트, Canvas, Audio API는 WebView만으로 MVP 구현이 충분했어요.
Apps in Toss 정책과 SDK 제약을 처음부터 반영하는 편이 나중의 재작업을 줄일 수 있었어요.

## 트레이드오프

일반 브라우저에서는 Apps in Toss SDK가 없기 때문에 광고, 햅틱, safe area API를 그대로 호출하면 깨질 수 있어요.
그래서 SDK 사용 지점마다 지원 여부와 예외 처리가 필요해요.

## 결과와 후속 작업

MVP는 WebView 앱으로 구현됐고, 브라우저 개발 환경에서도 흰 화면이 뜨지 않도록 fallback을 추가했어요.
실제 출시 전에는 Apps in Toss 환경에서 광고, 햅틱, safe area, 배포 번들 동작을 다시 검증해야 해요.
