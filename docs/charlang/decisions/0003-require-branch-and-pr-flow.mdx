# 브랜치와 PR 기반 개발 흐름 강제하기

## 상태

채택됨

## 날짜

2026-05-24

## 배경

개발 중 실수로 `master`에 직접 커밋하고 push한 일이 있었어요.
사용자는 이후 모든 변경을 기능 브랜치에서 작업하고 PR로 병합하는 흐름을 원했어요.

## 결정

로컬 git hook으로 `main`과 `master`에서 직접 커밋하거나 직접 푸시하는 일을 막아요.
작업은 `master` 최신화, 기능 브랜치 생성, 검증, PR 생성, 병합 후 최신화 순서로 진행해요.

## 고려한 대안

- 사람이 주의해서 브랜치를 확인하기
- GitHub ruleset만 적용하기
- 로컬 hook만 적용하고 원격 보호는 나중에 하기

## 선택 이유

사람의 기억에만 의존하면 같은 실수가 반복될 수 있어요.
로컬 hook은 실수를 바로 막고, GitHub ruleset은 원격에서 한 번 더 막는 역할을 해요.

## 트레이드오프

긴급 수정도 곧바로 `master`에 커밋할 수 없어요.
하지만 출시용 앱은 변경 이력이 중요하므로, 이 제약을 받아들이는 편이 더 안전해요.

## 결과와 후속 작업

찰랑에는 `.githooks`와 설치 스크립트가 들어갔어요.
GitHub 보호 규칙은 저장소 권한과 운영 정책에 맞춰 유지해야 해요.
