# PRO 광고 제거를 일회성 IAP로 제공하기

## 상태

채택됨

## 날짜

2026-05-29

## 배경

찰랑은 배너 광고와 휴식 진입 전 광고를 통해 수익화를 준비했어요.
다만 타이머 앱에서 광고는 집중 흐름을 끊을 수 있으므로, 광고를 원하지 않는 사용자에게 명확한 유료 제거 옵션이 필요했어요.

초기 PRD에서는 인앱결제를 범위 밖으로 두었지만, PRO 광고 제거를 이번 출시 전 수익화 범위에 포함하기로 했어요.
이 기능은 광고를 제거하는 단일 권한만 다루므로 구독보다 일회성 구매가 제품 메시지와 구현 복잡도 면에서 더 적합했어요.

## 결정

PRO 광고 제거는 Apps in Toss IAP의 일회성 구매로 제공해요.
타이머 화면 우측 상단에 검은색 PRO 버튼을 두고, 구매 다이얼로그에서 타이머 배너, 차트 배너, 짧은 휴식과 긴 휴식 전 광고 제거 혜택을 설명해요.

구매 성공 시 Apps in Toss Storage 래퍼에 PRO 소유 상태를 저장해요.
앱은 시작할 때 저장된 PRO 상태를 복원하고, 가능한 경우 IAP 주문 API로 미결 주문과 완료/환불 주문을 조회해 상태를 보정해요.
미결 주문은 PRO 지급 후 `completeProductGrant`로 완료 처리하고, 최신 관련 주문이 환불 상태면 로컬 PRO 상태를 회수해요.

PRO 상태가 true가 되면 배너 광고 컴포넌트는 렌더링하지 않고, 전면형 광고 훅은 광고 로드와 표시를 건너뛰며 카운터를 초기화해요.
구매 성공 직후에는 새로고침 없이 광고를 끄고 3초 동안 축하 오버레이를 보여줘요.
이후 `feature/refine-pro-confetti-and-spacing`에서 구매 경험을 다듬었어요.
PRO 버튼은 명시적인 z-index로 물결, 광고, 성공 효과와 겹칠 때도 의도한 위치에 남기고, 탭 햅틱과 구매 중 spinner를 추가해 중복 요청과 무반응처럼 보이는 상태를 줄였어요.
구매 성공 효과는 `react-confetti-boom`의 firework로 바꾸고, 다이얼로그 문구는 광고 슬롯 설명보다 집중이 끊기지 않는 이점을 먼저 말하도록 정리했어요.
또 광고 제거 직후에도 타이머 조작 영역의 세로 간격을 보존해서 결제 보상 때문에 주요 조작 버튼 위치가 갑자기 움직이지 않게 했어요.

## 고려한 대안

- 광고 제거를 구독 상품으로 제공하기
- 브라우저 localStorage 플래그만으로 PRO 상태를 관리하기
- 구매 성공 후 다음 앱 실행부터 광고를 제거하기
- 광고 제거를 광고 슬롯별로 나누어 판매하기

## 선택 이유

일회성 구매는 `한 번의 구매로 끊김 없는 집중`이라는 메시지와 잘 맞아요.
찰랑의 광고 제거는 지속적으로 서버 리소스를 제공하는 기능이 아니라 앱 내 광고 노출을 끄는 권한이므로, 구독보다 사용자가 이해하기 쉬워요.

Storage만 믿으면 미결 주문, 이미 소유한 주문, 환불 상태를 복구하기 어려워요.
그래서 앱 시작 시 IAP 주문 API로 보정하고, Apps in Toss 환경 밖에서는 실패 안내와 fallback을 유지하는 방식을 선택했어요.

구매 직후 즉시 광고를 끄는 것은 사용자가 결제 보상을 바로 체감하게 하기 위한 결정이에요.
다음 실행부터 적용하면 결제는 성공했지만 화면이 그대로인 것처럼 보일 수 있어요.

## 트레이드오프

IAP bridge는 Apps in Toss 지원 환경에 의존해요.
일반 브라우저에서는 실제 구매 검증을 할 수 없으므로, 로컬 검증은 실패 안내와 앱 안정성 확인에 그쳐요.

PRO 소유 상태는 로컬 Storage를 기준으로 즉시 반영돼요.
환불 회수는 다음 실행 또는 주문 보정이 가능한 시점에 반영되므로, 지원 환경에서 주문 API 호출 실패가 반복되면 회수가 늦어질 수 있어요.

Font Awesome 왕관 아이콘을 쓰기 위해 패키지 의존성이 추가됐어요.
아이콘 사용 범위가 PRO 버튼과 다이얼로그, 축하 오버레이로 제한되므로 번들 영향은 계속 확인해야 해요.

`react-confetti-boom`은 성공 피드백을 빠르게 개선하지만, WebView 성능과 레이어 충돌을 계속 확인해야 해요.
특히 타이머 배경 Canvas, PRO 버튼, 구매 다이얼로그, 축하 효과가 동시에 존재할 수 있으므로 z-index와 pointer event 경계를 흐리면 안 돼요.

## 결과와 후속 작업

찰랑 `feature/pro-ad-removal` 브랜치에서 PRO 버튼, 구매 다이얼로그, 성공 축하 오버레이, 즉시 광고 비활성화, Storage 복원, 미결/완료/환불 주문 보정을 추가했어요.
PRD도 인앱결제를 범위 밖에서 제외하고 PRO 광고 제거를 현재 기능 범위에 포함하도록 갱신했어요.

후속 `feature/refine-pro-confetti-and-spacing` 브랜치에서는 PRO 버튼 레이어와 햅틱, 구매 중 spinner, 혜택 중심 다이얼로그 문구, fade-out 닫힘 애니메이션, `react-confetti-boom` firework 효과, 광고 제거 후 조작 영역 간격 보존을 추가했어요.

검증은 TypeScript `noEmit`, lint, production build, `git diff --check`를 통과했어요.
Apps in Toss IAP 실제 구매, 상품 지급 완료, 미결 주문 복원, 환불 회수는 sandbox 또는 실제 앱 환경에서 최종 확인해야 해요.
