# WebView MVP와 디자인 시스템 선택

## 상태

채택됨

## 날짜

2026-06-14

## 배경

Spot Mystery는 앱인토스 미니앱으로 개발됩니다.
사용자는 모바일 WebView 안에서 온보딩, 지도 탐험, 검색 리스트, 상세 바텀시트를 빠르게 오가야 합니다.

초기 요구사항에는 다음 제약이 있었습니다.

- Tailwind CSS와 daisyUI 조합을 사용합니다.
- react-router로 명확한 라우팅을 구성합니다.
- 공통 컴포넌트와 도메인 컴포넌트를 분리합니다.
- Google Map을 사용할 예정이지만 API 키 없이도 개발과 테스트가 가능해야 합니다.
- 앱 로고는 URL이 제공되기 전까지 AIT 설정에 넣지 않습니다.

## 결정

React + Vite + TypeScript 기반 Apps in Toss WebView MVP로 구성했습니다.
디자인 시스템은 Tailwind CSS v4와 daisyUI v5 테마 `spotMystery`로 만들었습니다.

Google Maps API 키가 있으면 실제 Google Map을 사용하고, 없으면 정적 지도형 UI를 fallback으로 보여줍니다.
탐험 첫 화면에는 대표 마커 4개만 노출해 UI 복잡도를 낮추고, 전체 TOP 10 탐색은 찾기 탭에서 담당하게 했습니다.

## 고려한 대안

- 처음부터 실제 Google Maps API만 사용: API 키가 없으면 개발과 e2e 테스트가 막힙니다.
- 모든 장소 마커를 탐험 첫 화면에 표시: 요구된 UI 복잡도 기준에서 선택지가 과도해집니다.
- 로고 파일을 AIT `brand.icon`에 넣기: 앱인토스 플랫폼이 URL이 아닌 빌드 파일 로고를 인식하지 못한다는 사용자 제약과 충돌합니다.

## 선택 이유

- WebView MVP는 Tailwind, daisyUI, React Router 요구사항과 자연스럽게 맞습니다.
- fallback 지도는 API 키 없는 개발 환경에서도 핵심 플로우를 검증할 수 있게 합니다.
- 대표 마커 제한은 첫 시선 목적지와 선택지 수를 관리합니다.
- 로고 URL 대기는 앱인토스 검수 반려 위험을 낮춥니다.

## 트레이드오프

- 실제 로드뷰, 주변 부동산 가격, Google Maps 상세 기능은 API 키와 외부 데이터 연동 후 고도화가 필요합니다.
- 정적 장소 데이터는 MVP에는 단순하지만, 운영 단계에서는 CMS나 API로 분리해야 합니다.
- Pretendard는 CDN으로 불러오므로 네트워크가 제한된 환경에서는 시스템 폰트 fallback이 적용될 수 있습니다.

## 결과와 후속 작업

- MVP 기능 구현과 자동 테스트가 완료되었습니다.
- Google Maps API 키와 앱인토스 로고 URL이 준비되면 `granite.config.ts`와 지도 검증을 업데이트해야 합니다.
- 콘텐츠 규모가 커지면 장소 데이터 구조와 검색 인덱싱 전략을 재검토해야 합니다.
