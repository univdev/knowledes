# 아키텍처

Spot Mystery는 Apps in Toss WebView 미니앱으로, 현재는 프론트엔드 단독 MVP입니다.
장소 데이터는 정적 TypeScript 데이터로 시작하고, 지도는 Google Maps API 키가 있을 때 실제 지도 컴포넌트로 전환되는 구조입니다.

## 전체 구성

- 앱 프레임워크: React, Vite, TypeScript
- 라우팅: React Router
- 디자인 시스템: Tailwind CSS, daisyUI
- 지도: `@vis.gl/react-google-maps`
- Apps in Toss 연동: `@apps-in-toss/web-framework`
- 테스트: Vitest, Playwright

## 주요 모듈 경계

- `src/components/common`: 앱 공통 UI 컴포넌트
- `src/components/layout`: 앱 셸, 하단 탭 같은 레이아웃 컴포넌트
- `src/features/onboarding`: 첫 진입 튜토리얼
- `src/features/spots`: 장소 카드, 지도, 상세 바텀시트
- `src/routes`: 라우트 단위 화면
- `src/data`: MVP용 정적 장소 데이터
- `src/utils`: 거리 계산과 검색 로직

## 데이터 흐름

1. 사용자가 처음 접속하면 로컬 스토리지의 온보딩 완료 여부를 확인합니다.
2. 온보딩을 완료하면 `/explore`로 이동합니다.
3. 탐험 화면은 사용자 위치를 요청하고, 실패하면 서울 시청 좌표를 fallback으로 사용합니다.
4. 장소 좌표와 사용자 좌표를 이용해 거리 표시를 계산합니다.
5. 지도 마커 또는 검색 카드 선택 시 같은 상세 바텀시트 컴포넌트를 엽니다.

## 지도 전략

`VITE_GOOGLE_MAPS_API_KEY`가 있으면 Google Map을 렌더링합니다.
키가 없으면 같은 선택 흐름을 검증할 수 있는 정적 지도형 UI를 보여줍니다.

이 전략은 다음 이유로 채택되었습니다.

- API 키 없이도 UI와 테스트를 안정적으로 검증할 수 있습니다.
- 실제 배포 전 Google Maps 키 주입 지점을 명확히 분리합니다.
- 지도 API 장애나 키 누락 상태에서도 완전히 빈 화면이 되지 않습니다.

## 외부 의존성

- Google Maps API: 실제 지도, 마커, 추후 로드뷰 연결
- 앱인토스 WebView 런타임: 위치 권한과 앱 실행 환경
- Pretendard CDN: 기본 폰트 로딩
- 원격 이미지 URL: 장소 대표 이미지

## 바꾸면 위험한 부분

- `granite.config.ts`의 `brand.icon`은 사용자가 업로드 URL을 제공하기 전까지 채우면 안 됩니다.
- `test-results`와 `dist`는 빌드/테스트 산출물이므로 커밋하지 않습니다.
- e2e 복잡도 기준은 UI 품질 게이트 역할을 하므로 완화할 때는 근거를 문서화해야 합니다.
