# 아키텍처

## 전체 구성

근무안심은 Apps in Toss WebView로 실행되는 React 앱이에요.
초기 MVP는 서버, 로그인, 외부 데이터베이스 없이 브라우저 로컬 저장소를 기준으로 동작해요.

구성은 다음 책임으로 나뉘어요.

- Apps in Toss WebView 설정: 앱 이름, 브랜드 색상, WebView 빌드와 번들 생성
- React UI: 온보딩, 탭 내비게이션, 캘린더, 목록, 바텀시트, Drawer
- 로컬 도메인 상태: 사업장, 근무 유형, 근무자, 일정, 불참, 대타 배정
- 검증과 배포: lint, build, Playwright E2E, GitHub Actions 번들 업로드
- 로컬 하네스: Mesh 고유 제품 규칙과 범용 프론트엔드 UX 규칙 분리

## 데이터 경계

데이터는 사업장 단위로 분리해요.
현재 선택된 사업장이 바뀌면 일정, 근무 유형, 근무자 목록도 해당 사업장 기준으로 전환돼야 해요.

주요 데이터는 다음과 같아요.

- 사업장: 이름, 규모, 국가, 시간대
- 근무 유형: 이름, 20개 고정 팔레트 색상, 선택 시간대 목록
- 근무자: 이름, 성별, 전화번호, 이메일, 가능한 근무 유형
- 일정: 날짜, 시작 시간, 종료 시간, 근무 유형, 근무자 여러 명, 메모, 반복 생성 여부
- 대타: 불참한 원래 근무자, 실제 배정된 대체 근무자

## 주요 흐름

온보딩은 한 번에 모든 필드를 받지 않고, 사업장 이름, 규모, 위치를 순차 입력해요.
최초 사업장을 만든 사용자는 근무 유형 탭으로 이동해 가이드 흐름을 경험해요.

일정 등록은 단일 일정을 기본으로 시작해요.
반복 일정 체크가 켜지면 반복 요일, 종료일, 생성 미리보기를 보여주고 충돌이 있으면 저장하지 않아요.

대타 구하기는 불참 처리된 일정에서 시작해요.
같은 근무 유형이 가능한 사람 중 해당 시간에 근무 기록이 없는 사람을 먼저 보여주고, 그 외 근무자도 예외 후보로 함께 보여줘요.
전화번호가 있는 사람에게만 전화 걸기 액션을 보여줘요.

## 외부 의존성

- Apps in Toss Web Framework: WebView 설정, 번들 빌드, Apps in Toss 배포 업로드
- TDS Mobile: 키보드 위에 고정되는 단일 하단 CTA, safe area를 고려한 모바일 UI 컴포넌트
- React/Vite: 프론트엔드 런타임과 개발 서버
- Radix/shadcn 계열 컴포넌트: Select, Sheet, Dialog 등 접근성 있는 오버레이와 입력 컴포넌트
- Swiper: 일정 탭의 주간 캘린더 좌우 스와이프
- Playwright: 주요 UI 흐름의 E2E 검증
- GitHub Actions: PR 빌드 검증과 main/master 병합 후 번들 업로드

## 바꾸면 위험한 부분

- 사업장별 데이터 분리 규칙을 깨면 다른 사업장의 근무자와 일정이 섞일 수 있어요.
- 일정 탭의 주간 캘린더, 선택 날짜, 타임라인은 함께 움직여야 해요. 캘린더만 이동하거나 선택 날짜만 바뀌면 하단 일정 목록의 기준일이 불명확해져요.
- 타임라인 fade/scale 효과는 실제 스크롤 컨테이너의 보이는 영역을 기준으로 계산해야 해요. 화면 전체를 기준으로 잡으면 상단 캘린더나 탭바 아래에서 카드가 갑자기 잘려 보여요.
- 일정 카드는 실제 근무자를 기준으로 해야 하므로, 불참한 원래 근무자를 같은 가중치로 보여주면 관리자가 오해할 수 있어요.
- Apps in Toss WebView에서는 safe area, 하단 CTA, FAB, 탭바가 겹치지 않아야 해요.
- 키보드 대응 단일 CTA는 TDS Mobile `BottomCTA.Single`의 `fixedAboveKeyboard`를 사용해요. `BottomCTA.Double`은 같은 속성을 지원하지 않으므로 수정/삭제처럼 두 액션이 필요한 화면에 무리하게 적용하지 않아요.
- 배포 API 키는 GitHub Actions secret으로만 관리하고 저장소에 직접 기록하면 안 돼요.
